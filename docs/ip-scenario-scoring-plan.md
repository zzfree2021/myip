# IP 画像与场景评分改造方案

状态：已落地自动轻量访问检测；下文原始设计中的手动平台检测与不透明响应不评级策略，已由以下实施规则替代。完整网络质量与入站检测仍手动启动。

## 当前实施规则（2026-09-16）

- 打开详情页自动检测 12 类场景、65 个公开目标，共享并发上限 8；每个目标先获得首个样本，再最多补齐 8 次，每次请求上限 1.5 秒，整轮上限 20 秒。退出页面、重测或切换网络时取消旧请求。
- 默认直接请求预设的资源端点；支持读取的端点使用 CORS。跨域读取失败后只切换一次探测方式，不在每个样本中重复双请求。
- 至少 3 次有效响应，以 HTTP 响应耗时中位数的 ≤150、≤300、≤600、≤1000、>1000 ms 五档生成访问速度星级。该分数不是账号安全或业务可用性评分；IP 信誉独立展示。
- 可读拒绝响应、限流、取消、过期、样本不足不评级；请求异常显示独立记录，不当作 UDP 丢包。场景至少 3 个平台有效且覆盖 60% 后，才显示有效平台星级的算术平均（保留一位小数）及已评/总平台数；未评分项不计入平均分，覆盖不完整时详情明确提示部分结果。
- 支持 trace 的目标将出口观察复用到本轮采样，不额外串行等待。出口一致标注“该 IP 实测”；出口不同明确标注，星级仅代表当前网络；无法核验时仍展示当前网络访问结果。
- 场景列表采用网站连通页的斑马纹表格，覆盖圆点对应各平台；点击场景通过 ResponsiveDialog 查看均分、各平台结果及检测证据；桌面弹窗、移动端底部抽屉。详情复用站点图标、八次采样圆点与延迟徽标，每个平台可展开查看目标、来源、采样记录、时间、HTTP 状态与出口。未经实测的地址族显示未知。
- 流媒体自动检查网站接入，完整播放质量、游戏、会议网络质量与部署入站证据继续使用独立手动检测。当前模块内共享结果，重新打开页面重新探测，避免跨网络沿用旧结果。

## 1. 已确认的问题

- `src/views/ip/profile.ts` 按信誉分给出起始星级，再按住宅、移动、机房等类型封顶。没有接入实测证据，不能称为场景实测评分。
- `src/views/ip/latency.tsx` 的 Globalping 路径为「远端探针 → 被查询 IP」，不等于「这个 IP 作为出口 → 目标平台」。Worker 当前每个探针只发送 3 个 ICMP 包，也不足以代表长期稳定性。
- `src/views/link/api.ts` 有最多 8 次 HTTP 资源请求样本；底层 `probe()` 使用 `no-cors`。成功只证明取得了不透明响应，无法证明 HTTP 200、登录、对话、发布或地区授权正常。
- `src/views/ai/probe.ts` 部分平台可以校验边缘响应，但也明确不代表业务功能可用。
- 分流情况下，不同目标平台可能经过不同出口；不能用一次通用「我的 IP」查询给所有站点证明出口归属。
- 厂商行业、注册国家一致性都不是质量分；教育、政府、金融类型不能自动加分。信息级情报不能被当作威胁。

## 2. 界面：类型与分数使用不同的语义

复用项目现有 shadcn/ui `Badge`、`Card`、`Button`、`Progress`（如需加入）和 `ResponsiveDialog`。不再在各页面散落临时颜色。

扩展现有 Badge 的语义 variant，保留已有 variant 以免影响其他页面：

| 语义    | 展示对象                                                          |
| ------- | ----------------------------------------------------------------- |
| success | 已核验的良好结果，例如已返回的网络标记均未检出、业务探测通过      |
| info    | 中性类型：住宅、移动、机房、ISP、公共服务；未知数据使用低强调样式 |
| warning | 类型冲突、代理/VPN/Tor 标记、部分可达或测量异常；不自动等同恶意   |
| danger  | 明确滥用/威胁记录，或同一路径下经复测确认的业务失败               |

- 教育、政府、金融等非常见业务分类使用紧凑 Badge 突出；弹窗解释其用途。没有全网分布数据，不显示稀有百分比，也不因少见提高评分。
- 注册地不同是中性归属信息；只有明确冲突才使用 warning。
- 星级单独配色：1 星红、2 星橙、3 星蓝、4 星绿、5 星金色满星；未测、过期、无法验证用灰色状态，不显示 0 星。
- 保留顶部信誉分与红黄绿色带；它仍是数据源信誉指标，不能代替下面的实测星级。
- 场景默认一行显示「名称、星级或待测状态、证据状态」；展开后显示测量对象、路径、时间、样本、具体指标和未验证项。

## 3. 先建立可归属的测量证据

每条证据记录：被查询 IP、实际观察到的出口 IP、目标平台/主机、IPv4/IPv6、测量来源、方向、协议、时间、有效期、样本数、原始样本、结果状态和错误原因。

结果状态至少区分：未测、检测中、成功、部分成功、明确失败、限流、受浏览器/CORS 限制、路径不匹配、已过期。限流或无法验证不等于 IP 不可用。

证据分为三类，不混用：

1. **IP 画像**：归属、厂商、类型和风险记录。提供背景和独立风险提示。
2. **当前浏览器出口实测**：浏览器到目标平台的连通和网络质量。能够证明目标出口一致时才绑定到被查询 IP；无法证明时只标注为当前浏览器测量。
3. **目标 IP 入站实测**：远端探针到 IP/主机的 ICMP、TCP、HTTP 检查。用于部署/服务可达性，不能替代该 IP 的上网体验。

仅凭输入一个别人的 IP，无法从浏览器强制经过该 IP 发起请求。此时只能提供画像及适用的入站测试，访问类场景显示「未从该 IP 实测」。

## 4. 各场景的必需证据

| 场景         | 必需证据                                           | 不能据此断言                       |
| ------------ | -------------------------------------------------- | ---------------------------------- |
| AI 网页端    | 指定平台、同出口的有效响应、多次可达性与响应耗时   | 静态图标可达不等于登录/对话可用    |
| 跨境电商     | 指定平台/区域、同出口接入验证与重复测量            | 不判断店铺安全、独享性或账号通过率 |
| TikTok       | 指定地区、有效接入响应；上传体验需真实上传质量测量 | 不推断内容发布权限、推荐流量       |
| 加密平台登录 | 指定平台/地区的接入证据和风险状态                  | 不评价投资收益或资金安全           |
| 流媒体       | 下载、负载下延迟、丢包；内容地区授权另列           | 不以 IP 信誉推断解锁               |
| 游戏联机     | 目标区域的 RTT、抖动、真实丢包；NAT 数据单独列出   | HTTP 请求失败率不是 UDP 丢包率     |
| 远程办公     | 上下行、负载下延迟、抖动、丢包；企业访问策略另列   | 通用测速不等于某企业 VPN 可用      |
| API          | 指定端点、可读状态/预期响应、多次耗时与错误率      | 无鉴权探测不证明有调用额度或权限   |
| 网站部署     | 指定服务/端口的外部 TCP/HTTP 可达性、多地区复测    | ICMP 不回包不等于 HTTP 服务不可用  |

展示到具体平台/区域，避免给整个「AI」或「电商」类别一个无条件结论。地区支持未验证时单独列出，不默认为支持。

## 5. 星级生成规则

### 先满足证据门槛

- 缺少场景必需指标、出口不能关联、证据过期：`stars = null`，显示缺什么和「开始检测」。
- 403、429、CORS、超时分别记录；只有可确认且重复出现的有效失败才作为失败证据。
- 画像风险提示与网络实测星级分开，不能用低信誉伪造差网速，也不能用低延迟冲掉威胁提示。
- 5 星必须有完整且适用的实测指标；不得以默认值、仅画像或自动补满权重获得。

### 性能类优先复用公开评分规则

流媒体、游戏、实时通信采用固定版本 Cloudflare AIM 的指标和五档映射：bad/poor/average/good/great → 1/2/3/4/5 星。保存规则版本与实际测速端点。缺少必需项时先拦截，不把缺项当 0 或默认优秀。

这是到测速基础设施的网络质量参考，不能宣称是到所有游戏服务器、流媒体平台的实测结果。企业远程办公再单列目标应用可达性。

### 平台接入与部署类分阶段开放

第一版先展示真实可达性、响应时间、失败原因和证据覆盖，不凭空创建权重。收集住宅、机房、移动、代理、限流、禁 ICMP 等样本，校准并版本化规则后再开放数值星级。

仅有不透明资源响应时显示「资源可达，业务未验证」，不显示平台可用五星。业务验证只采用明确允许、可解释的只读检查，不触发登录、发布、交易等账号操作。

## 6. 测量流程与实现边界

- 页面加载先显示画像，不自动启动 9 组大流量测试。
- 场景点击「检测」后复用已有探测结果；支持取消，限制并发，共享同目标缓存。
- 保留现有 HTTP 8 次采样流程的含义。网络质量测试采用能提供所需指标的实现，不将现有 HTTP 耗时或 3 包 Ping 包装为抖动/丢包结论。
- 带宽测试单独启动并提前显示预计流量；不在移动端后台自动跑上传/下载。
- 测量 key 包含目标、路径/出口、协议、地址族和规则版本。变更出口、查询 IP 或目标平台后旧结果不能套用。
- 首期会话内保留短期实测结果；持续稳定性另行设计，不用一轮测试证明长期稳定或独享。
- `IpLatency` 的结果上移到详情页共享数据层，避免评分模块重复发起 Globalping 请求；同时保留其 inbound 来源标签。
- 拆开画像派生、探测执行、证据判断、评分映射和 UI 展示；纯评分函数只消费证据，不发请求。

## 7. 实施顺序与验收

1. **先纠正展示**：撤掉证据不足的启发式星级；新增 Badge 语义与星级色阶。验收：罕见行业不自动加分，机房不被染红，未知不显示 0 星。
2. **统一证据与检测入口**：接入已有 Ping/HTTP/目标出口记录。验收：查询非当前出口时不误用浏览器测试；分流、IPv4/IPv6、限流、过期和取消均有独立状态。
3. **接入网络质量实测**：流媒体、游戏、实时通信先采用公开规则。验收：原始指标可追溯，缺项不给星，切换网络不沿用旧分。
4. **校准平台与部署场景**：用具体端点/区域的可读结果和样本集制定规则。验收：资源响应不冒充业务通过，禁 ICMP 但 HTTPS 正常不判低分，风险提示不被高性能覆盖。
5. **UI 回归**：320/375px、桌面、浅深色、长 IPv6、未知类型、所有星级、键盘和移动说明弹窗。

回归样本特别包含：信誉 100 但 AI 不可达、同一浏览器分流两个出口、运营商禁止 ICMP、403 可达但被拒绝、上游 429、信息级「移动蜂窝」、高性能机房、缺少 packet loss 的测速结果。
